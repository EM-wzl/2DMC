# 2DMC beta1.8 · OpenGL

把 `beta/beta1.8.cpp`（9582 行、Win32 控制台 `CHAR_INFO` 字符渲染的 2D 沙盒）
完整重写为 **OpenGL 贴图渲染** 的图形版。全部功能保留，另加**耐久度系统**。

---

## 快速开始

```
build.bat              :: 图形版（无控制台窗口）
build.bat console      :: 控制台版（保留 stdout/stderr，调试用）
build.bat fast         :: -O0 快速语法检查
```

产物 `2DMC18.exe`，静态链接，**无任何第三方 DLL 依赖**。

贴图分两部分：
- **`assets/tiles/<英文名>.png`**：物品/方块图标，启动时载入（16×16 PNG，最近邻放大到 32×32）。
  换皮只要替换同名文件即可；**删掉某个文件就自动回退**到程序化画法。
- **`assets/tiles/ore_*.png`**：矿脉版贴图（见下）。
- **`assets/skins/*.png`**：**MC 皮肤**（64×64 或旧版 64×32），见下。
- 其余（实体、特效、UI）仍是启动时用代码画出来的程序化贴图。

### 玩家：MC 皮肤解析与换肤

MC 皮肤是「展开图」——头/身体/手臂/腿各有自己的贴图块（正面、侧面、顶面……），
整张画出来只是一堆错位的小方块。所以 [atlas.cpp](src/render/atlas.cpp) 的
`assemble_player_skin()` 会按布局把各部位的**正面**抠出来、拼成 16×32 的立绘
（宽高比 1:2，画 **1 格宽 × 2 格高**）。各部位正面在皮肤里的坐标：

| 部位 | 坐标 | 尺寸 | 拼到立绘 |
|---|---|---|---|
| 头 | (8, 8) | 8×8 | (4, 0) |
| 身体 | (20, 20) | 8×12 | (4, 8) |
| 右臂 | (44, 20) | 4×12 | (0, 8) |
| 左臂 | (36, 52) | 4×12 | (12, 8) |
| 右腿 | (4, 20) | 4×12 | (4, 20) |
| 左腿 | (20, 52) | 4×12 | (8, 20) |

> 左腿在 64×64 里的区块是 **(16,48)**，正面就是 (20,52) —— 不是 (0,48)。
> 这个坐标是拿官方皮肤实测的（见下），别凭印象写。
> 旧版 64×32 皮肤没有独立左臂/左腿，自动复用右侧那块。

**换肤**：把任意 MC 皮肤 png 放进 `assets/skins/`，游戏里 **Esc → 设置 → ★ 玩家皮肤**
点一下换下一张（选择会存进存档）。目录为空则回退到程序化小人。

> **人物/怪物的绘制锚点**：物理坐标是**脚点**（落地时停在地面格上沿），所以贴图按
> **底边**对齐到该点绘制。以前是按中心对齐，贴图会往地下多伸半个身位，看起来像
> 人卡在方块里（实际人是站在上面的）。飞行 Boss / 箭矢的坐标是**身体中心**，仍按居中绘制。

### 双图：世界里的矿脉 vs 背包里的物品

煤 / 粗铁 / 钻石 / 粗金 这几个 id 既是世界里嵌在石头里的矿脉、又是背包里的材料，

| id | 背包里显示 | 世界里显示 | 矿脉贴图 |
|---|---|---|---|
| 煤 coal | `coal.png` | 矿石 | `ore_coal.png` |
| 粗铁 raw_iron | `raw_iron.png` | 矿石 | `ore_raw_iron.png` |
| 钻石 diamond | `diamond.png` | 矿石 | `ore_diamond.png` |
| 粗金 raw_gold | `raw_gold.png` | 矿石 | `ore_raw_gold.png` |
| 下界金矿 | `nether_gold_ore.png` | 同左 | `ore_nether_gold.png` |

后两个 id 两边本就是方块贴图，所以内容一致。新增一种双图物品只需往

## ★ 耐久度系统（新增）

### 数据模型

物品堆栈从 `[id, count]` 扩展为 `{id, count, wear, flag}`（`src/item/item.h`）。
`wear` = 已损耗点数，0 表示全新。只有工具/武器/护甲/弓/盾有耐久，可堆叠方块恒为 0。

### 耐久上限（`src/world/blocks.cpp` 的 `max_dur` 字段）

| 材质 | 工具 | 头盔 / 胸甲 / 护腿 / 靴 |
|---|---|---|
| 木 | 59 | — |
| 石 | 131 | — |
| 金 | 32 | 77 / 112 / 105 / 91 |
| 铁 | 250 | 165 / 240 / 225 / 195 |
| 钻石 | 1561 | 363 / 528 / 495 / 429 |
| 下界 | 2031 | 407 / 592 / 555 / 481 |
| 暗影 | 2400 | 460 / 660 / 620 / 540 |

其他：木弓 384、风暴弓 512、恶魔弓 666、盾牌 336、OI 剑 2000、魔光剑 2400。

### 扣耐久规则

| 行为 | 扣点 |
|---|---|
| 成功挖掉一个方块 | 1 |
| 剑/斧命中实体 | 1 |
| 弓射出一次 | 1 |
| 护甲受击 | `max(1, 伤害/4)` |
| 工具/护甲耐久 ≤ 25% | 护甲值减半（护甲变薄） |

### 表现

- 物品格底部一条细耐久条，颜色随剩余比例 **绿 → 黄 → 橙 → 红**
- 剩余 ≤ 10% 时耐久条红色闪烁
- 快捷栏选中物品在 HUD 中央显示「`铁镐  耐久 187/250`」
- 耐久耗尽 → **物品碎裂消失**并提示「你的`铁镐`已损坏」
- 设置面板可一键关闭耐久度（`★ 耐久度`）

### 修复（合成面板第 8 页「耐久修复：」）

新增一整页修复配方，用材料把磨损补回来。**只有在物品确实有损耗时才能修**
（没磨损就不让浪费材料），修完耐久条立刻变长。

| 材料 | 可修物品 | 回复 |
|---|---|---|
| 1 铁锭 | 木/石/铁/钻石/金 镐、剑、斧，铁四件套 | 25% 上限 |
| 1 下界锭 | 下界 镐/剑/斧、下界四件套 | 33% 上限 |
| 1 暗影鳞片 | 魔光剑、恶魔弓、暗影四件套 | 33% 上限 |
| 2 线 | 木弓、风暴弓 | 25% 上限 |
| 2 铁锭 | 盾牌 | 25% 上限 |
| 1 OI 核心 | OI 剑 | 50% 上限 |

共 **32 条**修复配方。放在独立的一页而不是塞进旧页面，是为了不动旧版 68 条配方的
排列与页码（旧档玩家的肌肉记忆不会被破坏）。

## 与旧版的行为差异（刻意为之）

1. **`name[]` 缺逗号 bug 已修正**：旧版 `"smithing_table" "shadow_scale"` 被 C++ 拼成一项，
   导致 `name[]` 从 id 94 起相对 `test[]` **整体错位一位**（`/give shadow_helmet` 实际发的是暗影鳞片）。
   新版本按 `test[]`（中文名）重新对齐，**id 编号不变**。
2. **id 101「魔光护符」已补齐，102..150 仍为废弃残留**：旧版 `name[]` 有 151 项，但其中
   只有 `test[101]`（魔光护符）有中文名且被旧版实际使用（`setlight` 随身 12 级光、
   `hujia_update` +2 跳跃、配方 `7803` 可合成），故新版物品域为 **0..101**：
   `/give magiluminescence`、合成页③的「5暗影鳞片+5金锭->魔光护符」均可用。
   其余 id 102..150 没有硬度/等级/贴图数据，仍不纳入。
3. **随机数换成可播种的独立随机源**（`world::rnd()`），世界生成可复现（旧版每次开局地形不同）。
4. **负数硬度钳制**：旧版 `blockwj[]` 部分项为 -1（且 `blocklv[]` 有 -1），
   在 `wajue()` 里会做 `blocklv[负数]` 越界读。新版本统一走带边界保护的查询。
5. **挖掘有视觉反馈**：旧版挖方块是静默的，新版本有裂纹叠加层 + 碎屑粒子。
6. **地下有环境光下限**：旧版光照传播只覆盖玩家附近，大片洞穴 `light=0`——
   字符版靠白色前景色仍能看见轮廓，贴图版照搬会整屏全黑。新版本把可见度拆成
   「随深度上升的环境光下限」与「光照项」取 max，既有洞穴氛围又不至于瞎。
7. **开局送一套基础物资**（木镐/石剑/火把/苹果），旧版是空手开局。
8. 熔炉燃料 `rl` 现在**进存档**（旧版是运行时全局，每次启动归零）。
9. 第 1 页「1 原木 → 2 木棍」旧版是手写分支，背包放不下时不回滚（材料照扣只给 1 根）；
   新版本按标准配方处理，**放不下整体回滚**。

## 渲染技术要点

- **单张 512×512 图集**，32px 单元 × 16×16 = 256 槽位，方块 id 直接索引
- **顶点批渲染**：同纹理同状态合并成一次 draw call，整屏地形通常 3~10 批
- **平滑光照**：取每格四角相邻格光照做双线性插值写进顶点色，光照是柔和过渡而不是硬边方块
- **昼夜色调**：白天暖白 / 黄昏橙红 / 夜晚冷蓝，天空垂直渐变 + 星空 + 日月弧线
- **草皮覆盖层**：泥土/雪裸露在空气中时叠一条顶边（占 102..105 空槽位）
- **水波**：液面顶点随时间做正弦位移 + 表面高光
- **粒子**：挖掘碎屑、爆炸火花、水花、火焰、飘字
- **破坏裂纹**：10 级裂纹贴图随挖掘进度叠加

### 诊断开关（已留作回归工具）

| 开关 | 用途 |
|---|---|
| `--trace --frames=N` | 注入「一直按住 D + 每 40 帧跳一次」，逐帧记录玩家/相机位置 |
| `--drown` | 把玩家钉在水里，每 60 帧打印氧气与生命 |
| `--drownfast` | 同上但从 o2=8 开始，用来快速测溺水扣血速率 |
| `--seed=N` | 固定世界种子（可复现） |

### 实测记录

**相机抽搐**（`--trace`，101 帧样本）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 玩家 x 步长 | 中位 0.0485，最大 3.05，**5 次突跳** | 0.0669 稳定，**0 次突跳** |
| 玩家 y 反向次数 | **27 次** | **5 次**（全部来自跳跃） |
| 相机 jx 反向次数 | 3 | **0** |

**潜水**（`--drown`，玩家被钉在水下）：`o2=900` 起，1380 帧后 `o2=730`
-> 净消耗 0.125/帧，900 点约 **2 分钟**见底。

**溺水扣血**（`--drownfast`，从 o2=8 起）：o2 在 240 帧左右跌破 -20，
之后生命每约 90 帧掉 1 点，20 点生命约撑 **30 秒**。

**出生点**（`--seed=111/222`）：

```
seed 111 -> 干燥地表 x=5002 y=158  本体=天空 脚下=天空 脚下2=泥土 头顶=天空
seed 222 -> 干燥地表 x=5035 y=183  本体=空气 脚下=空气 脚下2=冰   头顶=空气
```

两种都是「脚踩固体、身体和头顶是空的」，不再出生在水里。

## 已知限制

- 鼠标左键攻击是「点一次打一下」（`mouse_pressed`），旧版是按住连打；
  要改回连打把 `entity.cpp` 里的 `lbutton()` 换成 `platform::mouse_down` 即可。
- 世界地图在默认缩放下约 10 万个面片（全屏地图本身就是重负载），
  放大到 4 px/格以上会明显更流畅。
- 实体贴图有 13 种，但「世界吞噬者」的体节晃动、凋灵的漂浮轨迹是简化实现
  （旧版是字符版，本来就没有）。
