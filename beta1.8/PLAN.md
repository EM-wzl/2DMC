## 0. 环境验证（已完成）

| 项目 | 结果 |
|---|---|
| 编译器 | MinGW g++ 16.2.0（`C:\mingw64`，UCRT POSIX SEH） |
| OpenGL | MinGW 自带 `GL/gl.h`、`GL/glext.h` + `libopengl32.a` |
| 链接 | `-lopengl32 -lgdi32 -lwinmm -static` → 静态自包含 exe，无 DLL 依赖 |

结论：**零第三方依赖**（不需要 GLFW/SDL/vcpkg/CMake），`build.bat` + `g++` 即可。

## 1. 总体思路

> **逻辑原样移植，只换渲染与 UI 层。**

原版把「世界状态 → 字符画」耦合在 `Print()` / `paint` 重绘逻辑里，逻辑本身
（地形生成、光照传播、实体 AI、战斗、合成、存档）是干净的纯计算。

所以重写策略是：

- **保留**：全部世界生成、光照、流体、实体 AI、伤害公式、合成配方、存档格式语义
- **替换**：`CHAR_INFO` 字符画 → OpenGL 贴图精灵批渲染；控制台光标排版 UI → 真实像素面板 UI
- **新增**：耐久度系统（物品/工具/护甲）

### 已存在的可复用基础（来自 `beta2.0/`）

| 文件 | 作用 | 复用方式 |
|---|---|---|
| `core/types.h` | 类型/颜色/Vec2/Rect/数学/xorshift | 直接复制 |
| `platform/platform_win32.cpp` | Win32 窗口 + WGL + 输入 + 计时 + 命令行 | 直接复制（+ WM_CHAR 钩子） |
| `render/renderer_gl.cpp/.h` | 顶点批渲染、纹理、图元、裁剪、UTF-8 文本、BMP 截图 | 复制 + 扩展逐顶点着色 |
| `render/font_gdi.cpp/.h` | GDI 按需生成中文字形图集 | 直接复制 |
| `render/atlas.cpp/.h` | 程序化纹理生成框架 | 复制框架，重画 101 个方块贴图 |


复用约 4000 行基础设施，把精力全部放在 beta1.8 的功能移植与贴图上。

## 3. 渲染层设计（贴图美观的关键）

### 3.1 图集布局

- 单张图集，`CELL = 32px`，`16 × 16 = 256` 槽位，全程序化生成（**无任何图片素材**）
- 槽位 0 = 纯白（画纯色矩形）
- 槽位 1..151 = 方块/物品（id 直接索引，便于查表调试）
- 槽位 160+ = 实体（玩家/僵尸/骷髅/苦力怕/蜘蛛/僵尸猪灵/OI/递归/蠕虫三节/羊/猪/凋灵/箭矢/爆炸/粒子）
- 槽位 224+ = UI（面板/格子/光标/心/护甲/气泡/耐久条/方向箭头）

### 3.3 物品图标（工具/装备/食物）

独立 `TS_I_*` 画法：镐/剑/斧/弓/箭/头盔/胸甲/护腿/靴/桶/药水/苹果/肉/金苹果/盾/鳞片/护符/宝石/锭/粒/棍/线/火药/桶装液体/魔光剑/恶魔弓……
每种 32×32 内做「斜置主体 + 描边 + 高光」的像素风，材质色板分木/石/铁/金/钻石/下界/暗影七套，一套色板多处复用（改一个色板即整体换色）。

### 3.4 世界渲染

- 一格 = **16 屏幕像素**（可在设置里调 12/16/20/24）
- 相机中心 = `(jx, jy)` 插值跟随（移植原版 `special_effect` 关/开/加强 三档）
- **平滑光照**：原版 `light[10000][1001]` 是逐格值（0..19）。渲染时取每格四角相邻格光照做双线性插值，写成 4 个顶点色 → 光照不再是硬边方块，而是柔和过渡
- **昼夜色调**：白天暖白、黄昏橙红、夜晚冷蓝，天空做垂直渐变 + 星空 + 太阳/月亮位置随时间移动
- **流体**：水半透明 + 水面顶点随时间做正弦偏移（水波）；岩浆自发光 + 呼吸脉动
- **实体**：精灵贴图（比一格大，非字符），受击闪白、朝向翻转、Boss 血条改为真正的 UI 血条（原版是 `====` 字符条）
- **破坏进度**：原版靠 `wj` 累积无视觉反馈 → 新增裂纹叠加层（0~9 级裂纹贴图）
- **粒子**：挖掘碎屑、爆炸火花、岩浆气泡、火把火星、水流溅射

## 5. ★ 耐久度系统（新增功能）

### 5.1 数据模型

物品堆栈从 `int [id, count]` 扩展为：

```cpp
struct Stack {
    i16 id = 0;          // 物品/方块 id
    i16 count = 0;       // 数量 0..64
    u8  wear = 0;        // ★ 已损耗点数（0 = 全新）
    u8  flag = 0;        // 保留位（附魔/特殊标记）
};
```

- 只有 `max_dur > 0` 的工具/护甲使用 `wear`；可堆叠物品恒为 0
- 堆叠合并时只合并满耐久物品；带损耗的工具各占一格（与原版 MC 行为一致）
- 护甲槽 `wear[4]` 同步保存各件的 `wear`

### 5.2 耐久参数表

| 材质 | 工具耐久 | 护甲耐久（头盔/胸甲/护腿/靴） |
|---|---|---|
| 木 | 59 | — |
| 石 | 131 | — |
| 金 | 32 | 77 / 112 / 105 / 91 |
| 铁 | 250 | 165 / 240 / 225 / 195 |
| 钻石 | 1561 | 363 / 528 / 495 / 429 |
| 下界 | 2031 | 407 / 592 / 555 / 481 |
| 暗影（新增） | 2400 | 460 / 660 / 620 / 540 |

特殊：弓 384、风暴弓 512、恶魔弓 666、盾牌 336、打火石类无。
数值集中在一张 `DUR[]` 表里，改一个数即全局生效。

### 5.3 扣耐久规则

| 行为 | 扣点 |
|---|---|
| 成功挖掉一个方块 | 1 |
| 用剑/斧攻击命中 | 1（剑）/ 2（斧劈方块） |
| 用工具挖「不该用它挖的方块」 | 2 |
| 护甲受击 | 每 4 点伤害扣 1（按受伤部位分摊） |
| 盾牌格挡成功 | 伤害值 / 5（向上取整） |
| 弓射出一次 | 1 |
| 工具挖到基岩/不可破坏方块 | 0（原版也是 0） |

### 5.4 损坏与提示

- `wear >= max_dur` → **物品碎裂**：移除该格、播放碎裂音效与粒子、
  屏幕提示「你的<铁镐>已损坏」
- 剩余耐久 ≤ 10% → 物品栏图标出现红色闪烁边框
- 悬停显示：`铁镐  耐久 187/250`，配彩色耐久条
- 快捷栏选中物品始终显示细耐久条（原版 MC 风格）

### 5.5 UI 表现（贴图化）

- 物品格内：底部 2px 背景槽 + 前景条，颜色按比例 绿 → 黄 → 橙 → 红
- 护甲槽：每件单独的耐久条 + 部位图标
- 新增「耐久度」页面/板块可查看全身装备损耗
- 破坏方块时的工具损耗会在物品栏图标上做一次轻微「抖动」反馈

### 5.6 修复系统（与锻造台联动）

在锻造台（id 93）新增修复配方：

- 同材质两件工具合并：`min(耐久和, 上限)`，符合原版铁砧逻辑
- 材料修复：铁镐 + 铁锭×1 → 回复 25% 耐久上限
- 下界合金修复：下界锭修复下界/暗影装备，回复 33%
- 修复消耗经验/材料，失败时保留原件不掉耐久

### 5.7 存档扩展（关键）

现有 v3 格式里箱子物品打包成 `id + count*1000`（16 位），**塞不下耐久度**。
方案：**新增 v4 格式，保持 v1/v2/v3 向后兼容读取**

- 文件头版本号 3 → 4；`TAG_WEAR`（护甲槽）扩展为 `TAG_STACKS` 标签，
  用 `tag + len + payload` 的既有机制承载「背包 100 格 × (id,count,wear,flag)」
- 箱子物品打包公式升级为 `id + count*1000 + wear*64000`（32 位足够），
  读取旧档时 `wear` 视为 0（全新）
- 旧 v3 存档首次加载后自动另存为 v4（沿用既有的「加载后重写」路径）
- **破坏性变更**：v4 存档不能再被旧 exe 读取（新功能必然如此）；旧档可读可升级
